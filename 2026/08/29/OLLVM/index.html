OLLVM -- 初识篇

发表于2026-08-29|更新于2026-08-29|CTF
|浏览量:

OLLVM是一个基于LLVM架构的代码混淆工具，它在编译阶段将正常的代码”打碎”并”包装”，让程序变得极其复杂难读。主要的混淆手段是三个部分，控制流平坦化，虚假控制流，指令替换

前情提要

LLVM18.8

LLVM是一套编译器基础设施项目，分为前端、中间层标识（IR）、后端。
前端就包括Clang、Rustc等，前端负责将对应语言的源代码转为中间层代码（IR），后端负责将IR转为特定平台的机器码或汇编代码。

PASS：

工作流程

PASS的工作就是，遍历IR也就是中间文件，同时对遍历的代码做出优化，插桩，混淆。
PASS的通常是.so文件。

四个PASS类型

1.ModulePass 基于模块

● 作用于整个编译单元（一个.c文件+所有头文件）。控制函数与函数之间的关系。
● 可以任意地添加、删除或修改模块中的任何内容，包括函数、全局变量、别名等。
● LLVM保证，在运行一个 ModulePass 时，不会并行运行任何其他Pass。
● 同时，ModulePass 也被允许修改其他函数，这是它与其他Pass的关键区别。
● 权限较大，因此一个 ModulePass 运行完毕后，关于函数内部的所有分析结果（比如数据流分析）都会被全部销毁，因为LLVM无法确定你改动了什么。

典型应用：

1.全局内联：决定将一个函数调用直接替换为函数体。
2.全局死代码消除：删除一个从未被调用的函数，或一个从未被使用的全局变量。
3.IPO（过程间优化）：如常量传播（将一个全局常量3.14传播到所有使用它的函数中）。
4.整体替换：将一个函数替换为另一个功能相同但实现不同的函数。

2.FunctionPass 基于函数

  1. 作用于单个函数内部
  2. FunctionPass是LLVM中数量最多、最常见的Pass类型，也是手写混淆（如OLLVM）和大多数标量优化的主战场。它每次只处理一个独立的函数。
  3. 由于这个PASS只作用于一个函数，所以具有多核并行的特点，比如同时运行8个FunctionPass处理不同的八个函数
  4. 保证不会修改任何其他函数，也不会增加或者删除某个函数
  5. 由于局限于只对某个函数有效，所以对全局变量和函数调用的信息不完整，无法修改函数原型
  6. 显式保留：FunctionPass 处理完一个函数后，任何没有被它显式标记为 Preserved 的分析结果（如循环分析、别名分析）都会被视为失效并被销毁。
典型应用：

1.OLLVM三大件：控制流平坦化、虚假控制流、指令替换（都是在单个函数内部完成的）。
2.大多数标量优化：常量折叠、死代码消除、表达式重关联等。
3.函数内简单的插桩：在一个函数的入口和出口插入统计代码。
OLLVM混淆中利用这个pass进行混淆，而恰好对应他的特征：代码膨胀但是不修改原有功能，流程图混乱但也都是表象。而且只改变单个函数，有利于隐藏混淆。

3.CallGraphPass 基于调用图

  1. CallGraphPass 可以看作是 ModulePass 的一个特化版本，它不直接操作函数内容，而是操作函数的调用关系图。
  2. 基于函数调用图（谁调了谁）、
  3. 遍历的是调用图的节点（函数）和边（调用关系）。可以在它提供的 runOnSCC（强连通分量）回调中编写逻辑。
  4. CallGraphPass 本身不允许修改函数的内容或调用图的结构。但奇妙的是，它可以通过返回 true 来“请求”LLVM再跑一遍自己，直到图结构稳定下来。
典型应用：

1.函数重排序：分析调用图，将调用频繁的函数在最终二进制文件中排布得更近，提高缓存命中率。
2.静态分析：分析哪些函数可能被递归调用。
3.为过程间优化做准备：标记哪些函数是纯函数（无副作用），以供后续优化使用

4.LoopPass 基于循环

1.单个循环内部
2.核心特点：它拥有嵌套层次意识。LLVM的循环管理器会保证：先处理最内层的循环，再逐步处理外层的循环。

典型应用：

1.循环展开：将循环体复制多份，减少分支判断次数。
2.循环向量化：尝试将循环中的标量操作转换为SIMD向量指令。
3.循环不变量外提：将循环内计算结果不变的表达式提到循环外面。
4.循环强度削弱：将循环内的乘法运算（i∗5）替换为代价更低的加法运算（
new_i = last_i + 5）。

OLLV中对Pass方法应用

🦁

混淆方式 (Pass 名称) 编译参数 核心操作方式 对 IR 的影响
控制流平坦化 (Flattening) -mllvm -fla 引入一个主分发器 (switch结构) 统一管理所有基本块的执行顺序。 彻底重构函数内的控制流图，原有的分支跳转逻辑被打散。
虚假控制流 (BogusControlFlow) -mllvm -bcf 为原始基本块克隆出虚假基本块，并通过插入一个永假或永真的不透明谓词，将这些虚假块链接到原始控制流中。 增加大量废话板块，会扰乱视线的代码块和跳转，使控制流图看起来极其复杂。
指令替换 (Substitution) -mllvm -sub 将简单的算术运算 (如 a + b) 替换为功能等价的、更复杂的指令序列 (如 a - (-b))。 不改变程序的控制流图，只是让反编译出来的代码看着更糟糕。
✦ OLLVM 混淆笔记 ✦

IR是Intermediate Representation（中间表示）

IR是LLVM架构中的核心部分：

  1. 前端：将你写的 C/C++/OC 等高级语言源代码，翻译成 LLVM IR。
  2. 中间层（核心）：OLLVM 的核心工作就在这一层。它通过各种“Pass（优化/混淆处理）”来分析和修改 IR。代码混淆（如控制流平坦化、指令替换）就是在这个阶段对 IR 进行的。
  3. 后端：将处理好的 IR 最终转化为特定平台（如 x86、ARM）的机器码。
    简单来说，无论源代码是哪种语言，LLVM 都会先把它们统一转换成 IR 这种中间语言，然后在这个语言的层面上进行所有分析和混淆操作。
    有几种表现形式：
    内存中文本，可读文本，二进制文本
    可阅读文本的转换命令：对应后缀应该是.ll

二进制：文本后缀是.bc

两种文件表示形式不一致，但均可被优化编译为可执行文件
特性：
● 静态单赋值形式：IR 代码采用 SSA 形式，意味着每个变量在代码中只被赋值一次。这极大地简化了数据流分析，为混淆算法提供了便利。
● 与平台无关：IR 本身不依赖于任何特定的 CPU 架构，这也解释了为什么 OLLVM 能轻松地将混淆后的代码编译到 ARM、x86 等多种平台。

OPT

opt为optimizer的缩写，优化器的意思，使用opt对IR进行优化操作。

● -load 加载指定的Pass进行优化（.so文件）
● -hlw LLVM Pass中自定义的参数，用来指定使用Pass的哪些功能，这个例子就是启动高等级混淆。
● -S同前面clang参数的作用相同，生成可阅读文本。

学会自己用PASS进行混淆：

写LLVM Pass 的原理，本质上就是：编写一个 C++ 类，继承 LLVM 提供的特定基类（如 FunctionPass），重写其中的 runOnFunction 方法，在里面遍历和修改 LLVM IR，最后通过宏将这个类注册成一个可被 opt 加载的插件。

LLVM Pass 编写核心步骤

  1. 编写代码：创建一个 .cpp 文件，包含头文件，定义一个继承自 PassInfoMixin 的 Pass 类，实现 run 方法，并编写插件注册代码。
  2. 编译：使用 clang++ 将源代码编译成动态库（.so 文件），链接 LLVM 库。
  3. 运行：使用 opt 命令加载生成的 .so 文件，通过 -passes= 参数运行指定的 Pass。

✨

Pass编写这一块，会了就相当于会了混淆。感觉自己混淆之后再自己破解也挺有意思的。不过也可能会出现自己为难自己的情况……

编写的时候要注意的是，一个Pass能运行起来的刚需步骤：

  1. 头文件与注册：Pass变成插件必须包含的头文件，完成插件注册、回调等。
  2. 定义与继承：定义Pass类并继承原有的Pass基类。
  3. 核心逻辑：编辑核心逻辑，即这个混淆插件具体要做什么。
  4. 注册模板：注册部分应该是固定一样的吧，直接套用模板应该就行。

一个关键问题：如果说知道混淆时候的Pass代码，那是不是反混淆的时候把Pass的核心逻辑逆向一下就行了？

答：是的，理解混淆Pass的实现是反混淆的第一步，逆向其核心逻辑就是还原被混淆代码的关键。

clang: error: no such file or directory 在 WSL 中使用了 Windows 风格的路径 (D:\path) 使用 WSL 路径格式，如 /mnt/d/path/to/file.c
opt -passname 语法不支持 新版 LLVM 默认使用新 Pass 管理器，不再支持旧版直接写 Pass 名的语法 使用新语法：opt -load-pass-plugin=./lib.so -passes="passname"
opt 报错 Option '...' registered more than once 环境中存在多个版本或不同方式构建的 LLVM 库，导致符号冲突 统一工具链：编译和运行 Pass 使用同一套 LLVM（如系统安装的 /usr/bin/clang-18 和 /usr/bin/opt-18）
Pass 编译成功，但运行时无任何输出 Pass 代码是为旧 Pass 管理器写的（如使用 RegisterPass），无法被新版 opt 识别和执行 代码适配：按新 Pass 管理器规范编写，使用 PassInfoMixin 和 llvmGetPassPluginInfo 注册
llvm-config 或 clang++ 找不到 缺少 LLVM 开发工具或环境变量 PATH 未配置 安装对应包（如 llvm-18、clang-18、llvm-18-dev），并确保其 bin 目录在 PATH 中
