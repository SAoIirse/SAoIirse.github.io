模板实例化还原

模板实例化概念

模板实例化= 编译器拿到模板定义 + 一组具体模板实参，生成对应的普通函数/类的过程

我理解模板是把”同一套逻辑”封装成一个可复用，或者说可随时调用的“函数”，但其本质上不是函数、不产生代码。程序中用具体类型去实例化的时候，编译器才在编译期生成对应的具体函数；每个满足模板内部要求的类型，会得到一份类型安全、可正常调用的独立函数

模板实例化形式

● 隐式实例化：调用时编译器推导类型并生成代码，可能在多个编译单元重复生成，链接器去重。
● 显式实例化：在指定位置集中生成一次，其他文件通过 extern template 直接引用，避免重复编译
显式特征： template
隐式没啥特征，是默认的编译器自动进行。

STL-利用模板构建的标准库组件集合

STL 大量使用 C++ 模板，而模板实例化会让这些通用组件针对具体类型生成相应的代码，在 C++程序中提供现成数据结构和算法。所以碰到使用 STL 的 C++ 程序时，就会遇到大量模板实例化产生的符号和机器码。

RRTI

RTTI（Run-Time Type Information）是 C++ 提供的运行时类型信息机制，使程序能够在运行期间查询对象的实际类型，并在一定条件下判断类型转换是否可行。
对于多态类，编译器通常会生成与类型相关的元数据，其中包含 RTTI 所需的信息。具体信息的布局和存放位置由编译器实现决定，常见实现会将相关类型信息放在程序的静态存储区域。
C++ 中与 RTTI 相关的主要功能包括：
● typeid：获取类型信息。
● dynamic_cast：在运行时检查特定的类型转换。

C++用 typeid 获取变量类型名称。

注意：typeid(p)获取的就是指针 p 本身的类型，而typeid(p)获取的是 p 指向的多态对象的实际类型。因为 p 是指针变量，而p 是指针解引用后指代的对象
● dynamic_cast：在运行时检查特定的类型转换。
tips: 变量类型分为静态类型和动态类型，通过基类指针或引用使用RTTI识别派生类的实际类型时，基类需要是多态类型。【这里认为静态类型和动态类型的判断和上一章虚函数表中判断实例静态动态类型原理和方式相同，当然这里仍然使用虚函数表指针关联虚函数表相关的 RTTI 信息】
IDA 能够还原类的继承关系，是因为编译器在编译 C++程序的时候在二进制文件中留有 RTTI 信息，IDA 通过分析这些信息，推断类型以及部分继承关系。

typeinfo 指针

这部分的本质还是理清结构体的内存布局与大小、成员偏移，以及类的继承关系。实际作用就是辅助静态分析，推断变量之间的引用关系、算清成员偏移。类的继承关系优先借助 RTTI 还原；结构体布局则主要靠分析汇编中 [寄存器+位移] 的内存访问，或者结合访问宽度推断成员类型。在 ida 中重新构建结构体操作详见：https://saoiirse.github.io/2026/07/21/VM%E8%99%9A%E6%8B%9F%E6%9C%BA%E9%80%86%E5%90%91/这块没啥必要单独学的，单独了解看这个吧，主要是 this 函数这块可以看看：https://systemk1t.github.io/2021/07/16/C-%E5%8F%8D%E6%B1%87%E7%BC%96%E4%B8%8E%E9%80%86%E5%90%91%E5%88%86%E6%9E%90-%E7%B1%BB/
