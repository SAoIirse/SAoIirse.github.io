HOOK--初识

发表于2026-09-26|更新于2026-09-26|CTF
|浏览量:

HOOK的作用
Hook技术能在程序实现正常功能的情况下，先于程序获取到程序的参数、信息、执行情况
● 监控系统中特定事件的发生并完成相应的功能，包括获取键盘和鼠标的输入信息，进而完成屏幕取词等功能
● 代码功能的嵌入，包括应用程序的补丁、程序的破解、插件的开发、系统中多种信息的隐藏等
所以其实说白了，就是在劫持程序流程，跳转到另外的一个程序中去，执行完程序B，再回到A程序。防御可以识别恶意代码行为，攻击也可以插入恶意代码行为。

HOOK的原理就是在程序运行过程中劫持程序流程跳转到另外的一个程序中去，执行完程序B，再回到A程序。防御可以识别恶意代码行为，攻击也可以插入恶意代码行为。

根据HOOK的对象hook技术可以分为：Message Hook，API Hook

Message Hook

● 线程钩子，可以监视指定线程的消息；
● 系统钩子，可监测整个系统内部的所有消息，由于会影响多个进程，需要进程注入；

Message Hook也叫做消息钩子，针对的是GUI（图形用户界面）程序
使用的关键Windows API函数SetWindowsHookEx， MSDN(Microsoft Developer Network)

SetWindowsHookEx结构体：

Windows API的函数，作用是安装一个钩子，能够监视系统或者某个线程的特定事件。

钩子类型常见参数：

钩子函数先看到应用程序的信息进行拦截，回调函数对信息作出处理，可能是修改或者打补丁等。在这个函数成功产生作用时，对监控的应用程序里注入一个动态的DLL。

Message HOOK时进程注入的原理：

两个程序相互独立，想要链接，就需要进程注入。要是对内存进行操作，并且获得进程地址里面的数据，或者修改进程的数据，修改程序执行流，就需要把代码放入到目的进程中。

Message Hook方式虽然简单，但是也存在不足， 它只能捕获Windows操作系统向用户提供的消息事件，诸如借助键盘、鼠标操作的事件等，也就是只能hook系统给的函数而不能hook自定义函数。

API HOOK

● 内联汇编Hook（Inline Hook）；
● IAT Hook等；
● API Hook是木马程序编写中的常用技术，在APT攻击中扮演重要角色

API HOOK原理：

  1. 程序从目标进程位置出发，首先是调用了WriteFile函数，然后跳转到了kernel32.dll
  2. 由于此时WriteFile已经被hook，开头的5个字节对应的汇编代码已经变成了JmpMyWriteFile，程序从kernel32.dll跳转到了 MyWriteFile当中
  3. 在MyWriteFile中，脱钩了WriteFile函数，执行了我们自己的代码以及WriteFile函数，程序从MyWriteFile位置又再次跳转到了kernel32.dll
  4. 在kernel32.dll中执行完WriteFile函数以后，返回到了MyWriteFile函数当中
  5. 最后再次hook了WriteFile函数，返回到我们自己一开始目标进程的位置

Inline API Hook

内联汇编是指在高级语言源码中直接嵌入汇编指令，并由编译器将其作为该函数代码的一部分一并编译的技术。而Inline API Hook就弥补了

实现步骤：

1.获取API的函数地址

2.修改API起始地址字节，使之跳转到我们自己定义的函数
这个程序是做到对程序内部直接修改需要跳转的地址，连接到我们自己定义的函数中去。也就相当于，用代码的方式改变了程序流

VirtualProtect

  1. 改变指定地址处，指定字节数量的可读可写可执行属性
  2. 获取WriteFile的地址
  3. 对WriteFile地址处的5个字节修改了属性，使该5个字节可读、可写、可执行
  4. 保存原始WriteFile函数的5个字节
  5. 获得我们的自定义函数MyWriteFile和WriteFile函数间的偏移，保存于变量pOffset当中
  6. 之后两次memcpy函数的调用修改了WriteFile起始地址处的5个字节
  7. 最后，恢复WriteFile函数处的代码属性

    0xE9是Jmp指令的字节码，其后跟随4个将会被解析为跳转偏移的字节码，这样一来，当我们调用WriteFile函数的时候，就会跳转到MyWriteFile执行

unhook
在自定义的函数中实现unhook（脱钩），恢复原API起始地址处字节。让程序回到原来的位置
脱钩函数在自定义函数中并不是必须存在的，如果不调用原来系统本身的API，可以选择不对函数进行脱钩,直接执行我们自己的代码
我们自定义的函数，函数的返回值，参数类型，参数个数要与被hook的API保持一致，目的是保证程序在运行过程中的堆栈平衡

如果执行完unhook之后，还需要二次hook就要再获取一次进程API

IAT HOOK

IAT Hook是 Windows 平台上一种常见的 API 函数劫持技术。它通过修改进程的 导入地址表（IAT） 中的目标函数地址，将对系统 API 的调用重定向到攻击者或开发者自定义的函数，以实现特定的功能或监控，IAT 存储了程序运行时需要调用的动态链接库（DLL）函数的实际地址。
IAT Hook对于32位的PE程序来讲，结构中有一个IMPORT Directory Table(IDT)，提供了关于IID结构体的相关信息，包括起始地址、时间戳等
针对每个动态链接库DLL，都存在一个 IMAGE_IMPORT_DESCRIPTOR（IID）结构，提供对DLL中函数的相关信息
IDT（中断描述符表）中对每个IID的描述长度为20字节，其中，最后20字节均为null用IMPORT Table的大小除以20，再减去1，就可以得到IDT的数量

IDT：告诉CPU当发生中断或异常时，该去哪里执行处理代码。
IDT就是一张映射表，索引号（0-255）对应不同的中断/异常向量，每个条目存储一个门描述符，指向对应的处理函数。

IAT Hook原理

● 在程序动态装载以后，先获得原始目标API的函数地址，然后保存在一个变量里
● 通过查找IAT的形式，找到IAT表
● 将IAT中的每一项的值和之前保存目标API函数地址的变量值进行比较，如果相同，则替换成我们自己函数的地址
● 局限性在于，程序必须动态装载才行

总结

Hook VM 解题 = 找到目标 RVA + 写数据采样/修改逻辑 + 批量 patch 字节码/解释器，实现对 VM 执行过程的监控和控制。
用HOOK解VM虚拟机的题目等
● 参数采样
● 状态变量观察
● VM 解释器 Hook
● 批量 patch 检查点
重要的是需要改动RVA和后面逻辑函数内容，bpt的内容对应你要对数据处理做法，RVA是目标指令在程序中的相对虚拟地址（也就是我需要下断点的目标指令，多断点的话就像是后面那样，RVA以初始化函数的形式展现。

注意事项

  1. 反调试对抗：很多 VM 题有反调试，可能需要先 patch 或绕过
  2. 地址重定位：RVA 需要加上 ASLR 后的基址（像你脚本里用 rebase()）
  3. Hook 时机：必须在 VM 初始化后、字节码加载后 Hook
  4. 多线程：VM 可能跑在子线程，需要确保 Hook 线程安全
