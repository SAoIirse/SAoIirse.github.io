PE文件格式[1]

发表于2026-09-27|更新于2026-09-27|《逆向工程核心原理》

本篇主要讲解PE文件部分内容，IAT和EAT等-请翻阅PE文件格式【2】。
PE文件是Windows系统中可执行文件格式，有exe,scr（可执行）,dll,ocx,cpl,drv（库）。想要在文件中打补丁或者修改程序硬编码，都需要对文件标志有所了解，甚至可以说是最好达到熟悉的程度
PE文件包括DOS部分、PE文件头和节表和节数据。从DOS头（DOS header ）到节区头（Sectionheader）是PE头部分，其下的节区合称PE体。节数据包括代码（.text）、数据（.data）、资源（.rsrc）节，分别保存。

重要结构体：

PEview看PE文件结构体如下：

VA&RVA

VA指的是，进程虚拟内存的绝对地址，RVA指的是从某个基准位置开始的相对地址。二者之间有一定的相互转换关系RVA+ImageBase=VA[其中ImageBase表示基准]
VA是程序运行时真正访问的地址，RVA是PE文件内部记录地址的方式。

DOS头

作用总结：标识文件类型，定位PE头。作为PE文件的文件标志。
IMAGE_DOS_HEADER (MZ文件头 0x40)

IMAGE_DOS_HEADER结构体的大小为40字节，需要注意的2个重要成员:

偏移地址 字段名 说明 示例值
0x0 - 0x01 e_magic DOS 签名，表文件开始标识 0x4d5a = “MZ”
0x3c - 0x3f e_lfanew PE 头部分的偏移 0x000000b0
在十六进制中：64个字节
B0的位置指向PE头，仅仅只有结构体中第一个成员和最后一个成员最重要，需要严格按照这个格式，不得修改。其他位置无所谓，可以修改或者全部填0。第一个是exe文件标识，最后一个是系统寻找PE头的标志。

DOS存根STUB

对现代系统无作用
非程序运行硬性要求，位置在DOS头下方，大小不固定。可以改动不影响程序运行
组成：代码+数据

在40-4D之间是16位的汇编代码，所以32位的程序是不支持，不认可的，也就会在反编译的时候忽略。当然，这部分被翻译为16位的汇编代码后，作用就是打印那个不能用DOS运行。

PE头

作用总结：描述 PE 文件的节表、入口点、数据目录等信息
第一部分：文件标志部分

PE–NT头-IMAGE_NT_HEADERS

PE签名 + 文件头 + 可选头，作为Windows系统解析PE文件的入口点。
单独看看PE文件头的结构图：

结构有三个成员组成:
签名结构体Signature，其值为50450000h(“PE”00)–>PE标识
文件头File Header,标准PE头
可选头Optional Header，扩展PE头
结构体大小为F8

NT头：文件头–IMAGE_FILE_HEADER

作用总结：描述文件的基本信息
20个字节

结构体有四个重要成员

偏移地址 字段名 说明 示例值
0x04-0x05 Machine CPU 类型 0x014c = “x86”
0x06-0x07 NumberOfSections 文件中节的个数 0x0003 = 3
0x14-0x15 SizeOfOptionalHeader 可选文件头大小 0x000e = 14

sizeofoptionalHeader:

和扩展头有关，标识扩展头字节大小,并且标识着文件位数大小。

可选头（扩展–IMAGE_OPTIONAL_HEADER()

IMAGE_OPTIONAL_HEADER的数据说明PE文件从哪开始执行、加载到哪、怎么对齐、用哪个子系统，以及最重要的——数据目录表指向导出/导入/TLS 等关键结构。
结构体中最大的部分，32位是224字节，

结构体：

十六进制文件对应：

字段 类型 说明 偏移 重要性
ImageBase DWORD 程序首选装载地址，内存镜像基址；决定内存镜像基址 0x1C ⭐ 重要
SectionAlignment DWORD 内存中节区对齐大小；决定中间空白部分大小 0x20 ⭐ 重要
FileAlignment DWORD 文件中节区对齐大小 0x24 ⭐ 重要

① Magic:

这是一个标记字,说明文件是 ROM 映像(0107h)还是普通可执行的映像(010Bh),一般是 010Bh，64位。如果是 PE32+，则是 020Bh。

④ Size0fCode:

有 IMAGE SCN_CNT_CODE 属性的区块的总大小(只人不舍 )，这个值是向上对齐某一个值的整数倍。例如，本例是 200h，即对齐的是一个磁盘扇区字节数(200h)的整数倍。在通常情况下，多数文件只有1个 Code 块，所以这个字段和.text 块的大小匹配。

⑤ SizeOfInitializedData:

已初始化数据块的大小，即在编译时所构成的块的大小(不包括代码段 )。但这个数据不太准确。

⑥ SizeOfUninitializedData:

未初始化数据块的大小，装载程序要在虚拟地址空间中为这些数据约定空间。这些块在磁盘文件中不占空间，就像“UninitializedData”这一术语所暗示的一样，这些块在程序开始运行时没有指定值。未初始化数据通常在.bss块中。

⑦ Address0fEntnyPoint:持有EP的RVA值，指出程序最先执行的代码起始地址。程序入口

程序真正入口地址：ImageBase+Address0fEntnyPoint
作用：程序执行人口 RVA。[真实入口地址：ImageBase + AddressOfEntryPoint]
对于 DLL，这个入口点在进程初始化和关闭时及线程创建和毁灭时被调用。通常指向运行时库代码，由它调用 Main/WinMain/DllMain。在 DLL中，这个域能被设置为 0，但此时收不到进程/线程通知。

⑧ BaseOfCode:

代码段的起始RVA。在内存中，代码段通常在 PE文件头之后，数据块之前。 在 Microsoft链接器生成的可执行文件中， RVA的值通常是1000h 。Borland 的 Tlink32 用 ImageBase 加第1个 Code Section的 RVA, 并将结果存入该字段。

⑨BaseOfData:

数据段的起始 RVA。数据段通常在内存的末尾，即 PE 文件头和 Code Section之后。可是，这个域的值对于不同版本的 Microso 链接器是不一致的，在 64 位可执行文件中是不会出现的。

⑩ ImageBase:

文件在内存中的首选载入地址。如果有可能(也就是说，如果目前没有其他文件占据这块地址，它就是正确对齐的并且是一个合法的地址),加载器会试图在这个地址载入 PE 文件。如果 PE 文件是在这个地址载人的，那么加载器将跳过应用基址重定位的步骤。

⑪SectionAlignment: 指定节区在内存中最小的那个

载入内存时的区块对齐大小。每个区块被载人的地址必定是本字段指定数值的整数倍。默认的对齐尺寸是目标 CPU的页尺寸。对运行在Windows 9x/Me下的用户模式可执行 文件，最小的对齐尺寸是每页1000h(4KB) 。 这个字段可以通过链接器的/ALIGN 开关来设置。在 IA-64 上，这个字段是按8KB排列的。

⑫ FileAlignment: 文件对齐属性

磁盘上 PE 文件内的区块对齐大小，组成块的原始数据必须保证从本字段的 倍数地址开始。对于x86 可执行文件，这个值通常是200h 或1000h, 这是为了保证块总是从磁盘的 扇区开始，这个字段的功能等价于NE 格式文件中的段/资源对齐因子。使用不同版本的 Microsoft链 接器，默认值会改变。这个值必须是2的幂，其最小值为200h。而且，如果 SectionAlignment 小于 CPU的页尺寸，这个域就必须与SectionAlignment 匹配。链接器开关/OPT:WIN98设置x86 可执行文 件的对齐值为1000h,/OPT:NOWIN98 设置对齐值为200h。

⑳ SizeOflmage:

映像载入内存后的总尺寸，是指载入文件从 ImageBase 到最后一个块的大小。 最后一个块根据其大小向上取整。
指定PE image在虚拟内存中所占空间大小。

⑳ SizeOfHeaders:

MS-DOS 头部、PE 文件头、区块表的总尺寸。这些项目出现在 PE 文件中的 所有代码或数据区块之前，域值四舍五入至文件对齐值的倍数。该值必须是FileAlignment的整数倍。
这个结构的大小，是存储的这几个文件对齐之后的大小。这个文件对齐是指，文件内存空间对齐，用空间换取时间

Subsystem

用来区分系统驱动文件和普通可执行文件
系统驱动：Driver文件（nyfs.sys）
窗口应用程序：GUI文件（notepad.exe）
控制台应用程序：GUI文件（cmd.exe）

NumberOfRvaAndSizes

用来指定DataDirectory(IMAGE_OPTIONAL_HEADER32)数组的个数。虽然结构体中明确定义了数组个数为16，但通过PE装载器来查看NumberOfRvaAndSizes值来识别数组大小。

DataDirectory:类似于结构体数组

是由IMAGE_DATA_DIRECTORY结构体组成的数组，数组每项都被定义的值。

节区头

作用总结：描述一个节区.text、.data、.rsrc的属性和位置
节表，每一个结构体成员是40个字节

在四个成员 之后，都是系统储存的垃圾信息，也就是编译器储存的常量字符串
创建成多个节区可以保证程序安全性，若把code与data放在一个节区相纠缠很容易引发安全问题。（溢出问题）所以每个区都需要分别设置不同的特性，访问权限等。

IMAGE_SECTION_HEADER（40字节）：

节区头是由IMAGE_SECTION_HEADER结构体组成的数组，每个结构体对应一个节区。

VirtualAddress，PointerToRawData不带有任何值，分别由SectionAlignment和FileAlignment确定。
VirtualSize，SizeOfRawData具有不同的值，磁盘中节区的大小和加载到内存中的节区大小是不同的。

Name字段

不以NULL结束，也没有ASCII的限制。PE规范未明确规定节区的Name，这里可以放入任何值，甚至可以填充NULL值。所以节区的Name仅供参考，不能保证百分百被用作某种信息。

不一样在头和节区空白，在运行的时候内存拉伸。
为什么对齐参数不同？因为节区进行了拉伸，所以中间增加了空白空间，那起始地址就不一样了
为什么要分为四个节区，设计成一段一段的？代码和资源还有数据之间不能混淆，如果data和test越界会出现漏洞

RVA和RAW

PE文件，从磁盘到内存之间的映射，要求每个节区都要准确完成内存地址与文件偏移的映射。RVA 和 RAW 是 PE 文件里最容易混淆的一对

对比项 RVA RAW
全称 Relative Virtual Address Raw Offset
中文 相对虚拟地址 文件偏移
视角 内存 磁盘文件
基准 ImageBase 文件开头（0）
对齐 SectionAlignment（通常 0x1000） FileAlignment（通常 0x200）
谁定义 VirtualAddress PointerToRawData
怎么算真实地址 ImageBase + RVA 直接读文件即可

RVA和FOA（RAW）的转换：

改变一个全局变量初始化地址。
RVA：相对虚拟地址。RVA=imagebase-内存地址
FOA：文件偏移地址
计算公式：前提：RVA 和 FOA 必须落在同一个节区内。

映射方法：

1）查找RVA所在节区
2）计算文件偏移（RAW）
RAW-PointerToRAWData=RVA-VirtualAddress
